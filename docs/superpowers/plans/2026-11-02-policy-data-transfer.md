# 정책 데이터 전달 구현 계획

**목표:** 사용자·계정 DB를 공유하지 않고 복지서비스와 저장 자격조건만 JSON으로 전달한다.

**구조:** 표준 SQLite/JSON 기반 서비스와 명시적인 CLI. 앱 설정 로딩, API 호출, 테이블 생성은 수행하지 않는다. 기존 스키마를 사용하는 DB만 지원한다.

## 안전 제약

- 두 정책 테이블의 허용 필드만 내보낸다. 조건의 로컬 기본키는 전달하지 않는다.
- 가져오기는 기본 미리보기이며, 실제 반영에는 `--apply`와 새 백업 경로가 필요하다.
- 서비스 ID로 갱신하고 해당 서비스의 조건만 교체한다. 나머지 정책과 사용자·계정·동기화 기록은 보존한다.
- 검증 후 단일 트랜잭션으로 반영한다. 실패하면 롤백하고 백업을 남긴다.
- 운영 DB 가져오기, 외부 API 호출, 커밋·푸시는 이번 작업에서 실행하지 않는다.

## 구현 순서

1. 격리 DB 테스트: 허용 필드, JSON 타입, 미리보기, 백업, 롤백, 개인정보 보존, 손상 파일 거부.
2. 내보내기·검사·가져오기 서비스와 CLI 구현.
3. README에 팀원 전달 절차와 제한 사항 추가.
4. 관련 테스트와 전체 백엔드 테스트, CLI 도움말, 공백 검사, 운영 DB 해시 보존 확인.

## 검토 중점

체크섬은 파일 손상 확인 수단이며 신뢰할 수 있는 발신자 확인을 대신하지 않는다. 백업에는 개인정보가 포함되므로 공유하지 않는다. 사용자별 결과는 각자의 프로필에 따라 달라지며 정책 파일 전달은 실시간 DB 공유가 아니다.
