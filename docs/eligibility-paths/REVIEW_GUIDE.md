# 자격 경로 검수 가이드

정책 원문을 **자격 경로 데이터**로 바꾸고 사람이 검수하는 방법이다. 1·2차 검수(정책 20개)를 하면서 정한 기준을 모았다.
데이터 형식과 판정 규칙은 [`README.md`](README.md)에 있다.

> 목표는 하나다. **신청할 수 있는 사람을 '불가'로 판정하지 않는다.**
> '가능'이 조금 넓게 나오는 것은 괜찮다(확인 사항으로 안내한다). '불가'는 사용자가 그 정책을 아예 보지 않게 만든다.

## 1. 한눈에 보기

```
API 원문 ─▶ 초안(LLM) ─▶ 사람 채점(채점 화면) ─▶ 수정·검수본 반영 ─▶ 시드 생성·DB 반영 ─▶ 진단
   ▲                                                                              │
   └──────────── 원문 해시가 바뀌면 그 정책만 다시 ◀──────────────────────────────┘
```

- **원문**은 정책 API 응답 그대로다. `지원 대상(target_details)` + `선정 기준(selection_criteria)`을 이어 붙인 것이고, 손대지 않는다.
- 정책 하나 = **경로 여러 개**(하나만 맞으면 신청 가능). 경로 하나 = **비교 조건**(모두 맞아야 함) + **확인 사항**(안내만).
- 검수하지 않은 정책은 기존 자동 분석으로 판정한다. 검수가 끝난 정책부터 경로 판정으로 바뀐다. 최종적으로 모든 정책을 경로 판정으로 바꾸는 것이 목표다.

## 2. 검수 순서

### ① 초안 만들기

정책 10개 정도를 한 묶음(차수)으로 초안을 만든다. 파일: `backend/data/eligibility_paths_batch{N}_draft.json`

```jsonc
{ "version": 2, "batch": 3, "status": "draft", "policies": [ { "serv_id": "...", "name": "...", "common": [], "common_checks": [], "paths": [], "preferences": [] } ] }
```

- 이미 검수한 정책(`eligibility_paths_reviewed.json`)과 겹치지 않게 고른다.
- 조건마다 `evidence`(원문 근거 구절)를 원문에서 **그대로** 복사해 넣는다. 자동 점검이 원문에 있는지 확인한다.
- 자동 점검: `python scripts/make_review_sheet.py data/eligibility_paths_batch3_draft.json ../docs/eligibility-paths/batch-3`
  - 입력 항목에 없는 `field`, 잘못된 연산자, 원문에 없는 근거 구절을 잡아 준다.

### ② 사람 채점 (채점 화면)

```bash
cd backend
python scripts/review_server.py data/eligibility_paths_batch3_draft.json   # → http://localhost:8765
```

- **왼쪽 원문, 오른쪽 LLM 판단**. 판단 줄에 마우스를 올리면 근거 구절이 원문에서 노랗게 표시된다.
- 판단(비교 조건·확인 사항·우대) **하나하나**를 `맞음 / 틀림`으로 채점한다. `틀림`이면 어떻게 고쳐야 하는지 적는다.
- 판단에서 빠진 조건은 정책마다 **놓친 조건** 칸에 적는다.
- 누를 때마다 `data/eligibility_paths_batch3_review.json`에 저장된다. 위쪽 번호로 정책을 오가고, 다 보면 `채점 완료 → 다음 정책`.

### ③ 반영

1. `*_review.json`의 `틀림` 메모와 `놓친 조건`대로 초안을 고친다.
2. 고친 정책을 `eligibility_paths_reviewed.json`의 `policies`에 `"batch": N`을 붙여 옮긴다.
3. 시드를 만들고 DB에 넣는다.

```bash
cd backend
python scripts/build_eligibility_paths.py && python scripts/load_eligibility_paths.py
python -m pytest -q
```

- `build_eligibility_paths.py`는 정책 원문을 스냅샷(`data/welfare-policies.json`)에서 읽어 원문 해시를 기록한다. 로컬 DB가 비어 있어도 된다.
- `tests/test_review_sheet.py`가 검수본 정책 수·중복·근거 구절을 확인한다. 차수를 추가하면 기대 개수를 고친다.

### ④ 판정 확인

프로필 5~6개(경계값·미입력 많은 사람 포함)를 정하고, **엔진을 돌리기 전에** 원문만 보고 정책마다 가능 / 확인 필요 / 불가를 적은 뒤 엔진 결과와 비교한다.
가장 먼저 셀 것은 **잘못된 불가**다(목표 0건). 기대 결과는 데이터를 만든 사람이 아닌 다른 사람이 적어야 더 믿을 만하다.

## 3. 판단 기준

### 비교 조건과 확인 사항 나누기

| 상황 | 이렇게 한다 | 예 |
|---|---|---|
| 진단 입력값으로 비교할 수 있다 | **비교 조건**으로 넣는다. 확인 사항에 두지 않는다 | 행복주택 총자산 → `가구 총재산`/`본인 총재산 lte` |
| 입력값으로 비교할 수 없다 | 확인 사항 | 자동차가액 3,708만원 이하, 성적 C0 이상 |
| 기준이 가구 형태마다 다르다(맞벌이·외벌이·가구원 수 조합) | 비교 조건에서 빼고, 형태별 기준 표를 확인 사항에 적는다 | 행복주택 신혼부부·고령자 소득 130/120/110/100% |
| 원문 조건이 입력보다 세밀하다 | 꼭 필요한 부분만 비교 조건, 나머지는 확인 사항 | 가스요금 '중증 장애인' → `등록 장애인` + "중증일 것" |
| 비교 조건과 같은 내용을 확인 사항에 또 적었다 | 하나만 남긴다 | 고령자 소득 조건 + 소득 기준 확인 사항 중복 |

### 잘못된 '불가'를 막는 규칙

- **누구 기준인지 맞춘다.** 원문이 본인 기준이면 `본인 총재산`, 세대·가구 기준이면 `가구 총재산`. 부모와 사는 청년을 가구 재산으로 비교하면 잘못 불가가 된다.
- **예정자·단서를 놓치지 않는다.** "입학 예정자 포함", "신청 월에 만 40세가 되는 자"처럼 대상이 넓어지는 단서(※ 표시 포함)는 놓친 조건으로 적는다.
  - 입력 안내로 해결되면 조건은 그대로 둔다. 예: 재학 여부 칸에 "입학·복학 예정이어도 '해당'" 안내를 넣었다.
- **조건이 없는 경로가 있으면 그 정책은 불가가 되지 않는다.** 원문에 "그 밖의 사람"처럼 조건 없는 대상이 있으면 경로로 남긴다.
- '가능'이 넓게 나오는 것은 괜찮다. 예: 미혼 대학생이 행복주택 '예비 신혼부부' 경로로 가능 → 결혼 가능성이 있으므로 그대로 둔다.

### 원문을 옮길 때

- **대상 설명은 원문 표현대로.** "구직자일 것"(X) → "저소득 구직자·청년·경력단절여성 등 취업 취약계층일 것"(O).
- **금액·수치 기준을 하나도 빠뜨리지 않는다.** 경로가 여러 개면 경로마다 확인한다(행복주택은 7개 경로에서 자동차 기준이 빠졌었다).
- **공통 확인 사항에 일반론을 넣지 않는다.** "공고 기준 확인", "유형별 기준 충족"처럼 원문 어디를 말하는지 알 수 없는 문장은 빼고, 실제 기준을 해당 경로에 적는다.
- **'또는'은 경로를 나눠서** 표현한다. 가점·우선선발은 `preferences`에 두고 판정에 쓰지 않는다.

## 4. 입력 항목이 부족할 때

원문 조건을 비교할 입력이 없으면 일단 확인 사항으로 두고, 같은 조건이 여러 정책에서 나오면 입력 항목 추가를 검토한다.

- **추가하기 쉬운 것**: 칸 하나로 해결되는 것. 예: `본인 명의 재산`(본인 기준 자산). 비워 두면 1인 가구는 가구 재산을 쓰고, 그 밖은 '확인 필요'로 둔다.
- **미루는 것**: 판정 엔진에 새 조건 형식이 필요한 것. 예: 맞벌이 여부(가구 형태 × 가구원 수 조합으로 기준이 바뀜). 해당 정책이 적을 때(152개 중 4개)는 확인 사항으로 둔다.

새 입력 항목을 만들면 `structured_condition_service.user_values`에 항목 이름을 추가한다. 채점 화면과 자동 점검은 이 목록을 그대로 쓴다.

## 5. 로컬에서 결과 화면 보기

```bash
cd backend
python -m scripts.policy_data import --database youth_welfare.db --source data/welfare-policies.json --apply --backup <백업 경로>
python scripts/load_eligibility_paths.py
```

`backend/.env`에 `USE_STRUCTURED_CONDITIONS=true`, `USE_ELIGIBILITY_PATHS=true`를 넣고 백엔드를 띄운 뒤 프론트에서 진단한다. 결과 화면은 검수한 정책만 기본으로 보여 준다.
