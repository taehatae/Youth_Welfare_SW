통합일: 2026-11-06. 작업 브랜치: `Hwang`.

사용자가 수정본 v2를 현행 예비 자격 판정 설계로 통합하도록 승인한 뒤 기존 절차를 실행했다. [revision-1](revision-1/README.md)과 [revision-2](revision-2/README.md)의 통합 보류·조건부 권고는 당시 검토 이력이며, 이번 승인으로 데이터 통합 단계에 진행했다. 기존 기록은 수정하지 않았다.

통합 전에 기존 파일·정책 객체의 SHA-256을 메모리에 기록하고 이후 대조했다. 원본 초안, 사람 채점, 수정본 1·v2, 1~3차 검수 자료, 정책 원문 스냅샷은 덮어쓰지 않았다. 검수본·시드는 기존 Git 추적 파일이므로 이전 커밋에서도 복구 가능하다. 별도 사용자 DB 백업이나 DB 파일은 생성하지 않았다.

## 검수 완료의 의미와 알려진 판정 한계

**사람 검수 완료는 원문을 자격 경로 데이터로 옮기는 작업에 대한 검수다. 특정 사용자의 모든 법적 자격이나 실제 선정 가능성을 검증했다는 뜻이 아니다.**

`conditions`는 입력값과 비교하고, `checks`는 추가 확인 안내이며 판정 상태를 직접 바꾸지 않는다. 아래는 실제 평가 코드에서 확인한 현행 동작이다.

- **미소금융**: 차상위 여부만 통과해도 다른 세부 자격·제외 여부가 미확인인 채 `eligible` 가능.
- **장애수당**: 등록장애·수급/차상위 조건을 통과해도 소득·학교별 제외·심사 가구 등 미확인 사항이 남은 채 `eligible` 가능.
- **청년미래적금**: 넓게 설정한 나이 조건을 통과하면 병역·가입일·소득·금융소득 정보가 미확인이어도 `eligible` 가능. 19~40세 자동 비교는 실제 병역 예외 확인이 아니다.
- 비교 조건이 없는 9개 경로 자체는 `needs_review`다. 같은 정책의 다른 OR 경로가 통과하면 정책 전체는 `eligible`이 될 수 있다.

후속 과제는 확인 사항 중 **판정을 보류해야 하는 미확인 필수 요건**과 단순 안내를 사람이 구분할 수 있는 구조 및 평가 규칙이다. 이번에 엔진·API·사용자 입력 구조를 바꾸거나 모든 확인 사항을 일괄 차단하지 않았다.

### 프론트엔드 안내 확인

`frontend/src/features/diagnosis/ResultPage.tsx`는 신청 가능을 '입력한 정보로 비교한 조건을 모두 충족하는 경로가 있음'으로 설명하고, 비교 불가능한 조건은 카드의 확인 사항을 보도록 안내한다. 하단에는 사전 안내이며 최종 수급 자격·신청 가능 여부를 담당 기관에서 확인하라고 명시되어 있다.

최종 행정 자격이 확정됐다고 표현하는 문구는 해당 안내에서 발견하지 못했다. 다만 '신청 가능'이라는 제목만 읽으면 오해할 여지가 있으므로 확인 사항과 주의 문구를 함께 보여 주는 현재 구조를 유지해야 한다. 이번에 프론트엔드 파일은 변경하지 않았으며 브라우저 실행 검증은 하지 않았다.

## 가상 프로필로 화면 확인하는 방법

### 사전 조건

이번에는 DB 적재가 금지되어 있어 새 시드를 운영 DB나 기존 로컬 진단 DB에 넣지 않았다. **시드 파일을 재생성한 것만으로 실행 중인 DB의 기존 자격 경로가 갱신되지는 않는다.**

새 40개 검수 결과를 화면에서 보려면, 이후 별도 승인된 절차로 원문 스냅샷과 최신 시드가 준비된 **격리된 수동 확인용 DB**가 필요하다. 이 문서의 서버 실행 단계는 그러한 DB가 준비된 뒤 사용한다. 기존 DB에서 아직 30개가 보인다고 이번 파일 통합이 실패한 것으로 단정하지 않는다.

### 실행

백엔드 터미널에서 **실제로 준비된 격리 DB 절대 경로**를 지정한다. 아래 `<...>`는 실제 경로로 바꿔야 하며, 운영 DB를 넣지 않는다. 설정은 해당 PowerShell 프로세스에만 적용한다.

```powershell
cd backend
$testDbPath = (Resolve-Path -LiteralPath '<준비된 격리 DB 절대 경로>').Path
$env:DATABASE_URL = 'sqlite:///' + ($testDbPath -replace '\\', '/')
$env:USE_STRUCTURED_CONDITIONS = 'true'
$env:USE_ELIGIBILITY_PATHS = 'true'
$env:USE_LLM_JUDGE = 'false'
.\.venv\Scripts\python.exe -B -m uvicorn app.main:app --reload --port 8000
```

주의: 앱 시작은 연결된 DB에 테이블을 생성할 수 있고, 빈 자격 경로 테이블은 진단 시 자동 시드될 수 있다. 따라서 읽기 전용 점검이나 운영 DB 보존 단계에서 위 서버를 무심코 실행하지 않는다. 이 작업에서는 서버를 실행하지 않았다.

다른 터미널에서:

```powershell
cd frontend
pnpm dev
```

접속: <http://localhost:5173>. Vite는 `/api`를 <http://127.0.0.1:8000>으로 전달한다. Swagger 주소는 <http://127.0.0.1:8000/docs>다. 새 의존성 설치나 설정 파일 변경은 수행하지 않았다.

### 확인 순서

1. 격리 DB의 테스트 계정으로 로그인하거나 가상 계정을 만든다. 실제 개인 프로필을 사용하지 않는다.
2. 연령 경계·미입력·등록장애·차상위·고용 상태가 다른 가상 프로필로 진단한다.
3. 사람 검수 필터를 켜고 4차 정책 10개가 포함되는지 확인한다. 비교 불가 경로가 섞인 정책은 확인 필요가 남을 수 있다.
4. 대표 자격 경로, 충족/미충족 조건, 추가 확인 사항, 내 정보와 정책 기준을 확인한다.
5. 위 세 정책은 `eligible`이어도 확인 사항이 남는다는 점을 확인한다. 이를 최종 행정 자격 승인으로 해석하지 않는다.
6. 필터를 끄면 미검수 112개도 볼 수 있는지, 변환본이 사람 검수 완료로 잘못 표시되지 않는지 확인한다.

이 수동 화면 확인은 아직 수행하지 않았으며 통과했다고 보고하지 않는다. 커밋·푸시·PR·dev 병합도 수행하지 않았다.
