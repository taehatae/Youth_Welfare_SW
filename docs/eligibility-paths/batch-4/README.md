## 원문 및 작성 원칙

근거는 [정책 원문 스냅샷](../../../backend/data/welfare-policies.json)의 `target_details`, `selection_criteria`다. 새 API 조회·운영 DB 조회 없이 저장된 원문을 사용했다. `support_content`의 지원 금액이나 대출 한도를 신청 자격으로 옮기지 않았다.

- `paths`끼리는 OR, 경로의 `conditions`와 `common`은 AND다.
- `checks`와 `preferences`는 판정에 쓰이지 않는다. **확인 사항을 넣었다고 `needs_review`가 강제되는 것은 아니다.** 비교 조건을 통과하면 확인 사항이 남아도 신청 가능으로 나올 수 있다.
- 비교 조건이 하나도 없는 경로는 확인 필요로 남는다. 이를 숨기거나 원문에 없는 필수 조건을 넣어 없애지 않았다.
- 국적과 거주, 보호자와 신청자, 총재산과 순자산, 본인 소득과 부부합산·과세소득·매출을 구분했다.
- `evidence`는 원문 구절이다. 확인 사항은 해당 원문을 요약한 문장으로, 아래 항목은 반드시 사람이 의미를 검수해야 한다.

## 사람 검수 웹페이지

저장소 루트에서 다음 명령으로 실행한다. 운영 백엔드·DB 로딩 없이 기존 검수 도구만 사용한다.

```powershell
cd backend
.\.venv\Scripts\python.exe -X utf8 -B scripts/review_server.py data/eligibility_paths_batch4_draft.json
```

접속: <http://localhost:8765>. 포트가 사용 중이면 마지막 인수로 `8766`을 지정한다.

1. 왼쪽 원문과 오른쪽 판단을 대조한다.
2. 각 비교 조건·확인 사항·우대를 맞음/틀림으로 채점한다. 틀리면 수정 메모를 남긴다.
3. 정책별 놓친 조건·경로도 기록한 뒤 채점 완료한다.
4. 저장 결과는 `backend/data/eligibility_paths_batch4_review.json`이다. 초안과 원문을 고치지 말고 의견을 여기에 남긴다.

사람 검수가 끝난 뒤 별도 지시에 따라 수정본 작성·검수본 통합을 진행한다. 현재 단계에서는 `merge_reviewed.py`, `build_eligibility_paths.py`, `load_eligibility_paths.py`를 실행하지 않는다.
